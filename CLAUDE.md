# Compendium

Web app and addon are both Compendium (the addon was Chronicler until 1.0: folder `addon/Compendium`, SavedVariables `Compendium.lua`, `/comp` or `/compendium`, TOC icon `INV_Misc_Book_09`; installing from the web app removes the old Chronicler folder, the live line prefix `CHRON1~` is unchanged). WoW addon (`addon/Compendium`, Lua 5.1) + a no-build web app (`web/`) hosted on Netlify with data in Supabase (`supabase/schema.sql`). The gaming PC (Windows) and recording computer (Mac, OBS) each run the web app in Chrome; the server clock bridges them. See README.md and docs/ROADMAP.md.

## Working with the user

- Don't include the ZIP download link in messages. The addon installs and updates from the web app (This computer › Update addon). Netlify deploys this branch automatically on every push: never ask the user to trigger a deploy (each manual deploy costs build minutes on top of the automatic one). Batch related changes into one push. Only two things need telling: re-running `supabase/schema.sql` after a schema change, and updating the addon in game after an addon change.
- Whenever you mention a file, say where it is or how to open it: a GitHub link for files in this repo
  (`https://github.com/adelrio3/streamer-app/blob/<branch>/<path>`), the full Windows path for files on their PC
  (e.g. `C:\Program Files (x86)\World of Warcraft\_classic_era_\WTF\Account\<ACCOUNT>\SavedVariables\Compendium.lua`),
  or the web address / menu path for external services (Supabase, Netlify). Don't say "the schema file" or "the README" bare.
- They play Classic Era (interface 11509 as of 1.15.9) on a Windows PC (Chrome can't open Program Files, so WoW gets moved to `C:\Games\World of Warcraft`) and record with OBS on a separate Mac (no file sharing between them), editing in Premiere Pro.
- Give exact values to enter and direct links (Supabase dashboard links can use `https://supabase.com/dashboard/project/_/...`), so they don't have to hunt or guess.

## Web app layout

- `web/index.html` is a sidebar shell (Chronicle: Overview, Characters, Lore / World: Locations, Quests, Storylines, Bestiary, People, Items / Footage: Recordings, Highlights, Shorts, Episodes, Footage finder, Marks, Narration / Stream / System); pages live in `web/app.js` as `pages.<name>` and use `pageHead`, `tabsHtml`, `crumb`, `facts`, `table`. **World is a personal wiki**: it lists only what this account has come across (from the addon's log), measured against everything in Classic (the database). A name is grey (`wikiName`, class `dim`) until done: a creature until hunted (never a kill count in the name; kills are "hunts"), a person until met, an item until obtained (`dim-item`), a quest until turned in, a zone until visited; nothing from the database is listed that the player has not found, and the whole-game totals only feed percentages. The World entries in the sidebar carry a percentage (`navPercents`, cached on `derived().navPct`, `.pct` spans with a shine when they change). Locations and Quests share `rpgMenu` (continents → zones by level → the page; `.rpg` in styles.css): it re-renders only what changed on clicks (`history.pushState`, no route), folds to a rail once a zone is chosen (`.rpg--zone`), and takes `detail(continent, zone)` / `after()` from the page. Locations' page is the zone's wiki entry (its map via `wireMap('locMap')`, areas discovered, quests, people, creatures as found), Quests' page is the zone's quest progress with the quests you logged there; the "Class, profession & events" tab counts those on their own. A quest page (`pages.quest`) shows the quest as read (text, objectives; the giver and turn-in as met, chain links only to quests found, spawn pins only for people met and creatures hunted) with your history last; `requirementText(q)` names the faction/race/class when a quest is not for everyone and `excluded` (not in the game) quests are hidden. People: `peopleStatus(n)` = met / seen / ambient (nothing to say or sell: met on sight); world.js merges NPCs with the same name into one entry (`mergeNpc`, `ids`). Loot `src` is `bought` at a vendor and `mail` at a mailbox (`ns.lootContext` in Capture.lua). The Footage nav entries carry `data-needs="records"` and hide on a computer that does not record. Storylines uses the same `rpgMenu` (continents → the zone each chain begins in → the chains started there; class/profession chains under Elsewhere) and lists only chains you have set foot in (chapters you have not found stay grey). **Nothing undiscovered from the database is ever shown except locations**: map pins (no count badges) come only from your own sightings (`ownSpots` from world's `spots`, never the database's spawn list) of people met, creatures hunted and objects opened (`pinsFor`, `dbQuestBody`); `dbMapPins` returns nothing, and an unfound quest, NPC or zone page (`dbQuestPage`, `dbNpcPage`, `dbZonePage`) shows a name, a zone and a count at most. Bestiary is `world.creatures` by kind (`CREATURE_TYPES`), People is `world.people` by zone, Items is `world.items` by kind → type (`itemKind` folds Projectile and Quest into Miscellaneous as its Projectiles / Quest items types, `MISC_KINDS`/`MISC_SUBS` keep the totals right; a kind's page is tabs, "All …" first, over one table; totals from `web/data/classic/itemdb.json`, `itemTable()` lazy-loads it; `obtained` = looted/received/created/worn/carried), Gathering is `world.objects`. Characters: the page lists the character cards, a "playing now" card from the live row for a character not yet uploaded (`liveCharacterCard`), and a Reach panel (`coverageGaps`, counts only and the race/class/profession that would open them, never a quest name: `web/lib/roster.js` `mergeRoster` turns the known characters into race/class/profession entries, professions from the skills the addon saw; `rosterCoverage(db, roster)` measures what that set can never reach: `unreachable` grouped `byReason` (race/class/profession and their pairs, or `combination` when the race and class exist but never together) and `choices`, groups of mutually exclusive quests (`ex`, excluding same-name race variants) with a bipartite matching of characters to branches; there is no roster to type in, characters appear as they log in). Each character page has Dashboard (`characterDashboard`: where they are, standing, quests in the log, storylines in hand, latest milestones), Progress (stats, gear, quests, recordings), Completion (`characterCompletion`, `?tab=completion`, `places` still routes there: the character's own quests done against what it can do, storylines started/finished, zones and areas, hunts, a zone-by-zone table, next chapters, loose ends folded per zone from `web/lib/coverage.js`, maps explored; `#/zone/<name>` is a zone's journal detail, and a `#anchor` after a hash path scrolls to it) and Journal (the character's first-person account by `web/lib/narrative.js` `journalEntries()`: I/me/my, exactly one entry per outing, the errands handed in retold as deeds from their objective text ("For Gornek I thinned ten Mottled Boars", never a quest title), grouped by who asked, length scaled to how much got done (one paragraph for a quiet outing, up to three for a busy one, `paragraphs`); `info.sex`, which the addon records with `UnitSex`, is shown as "Male Troll Hunter" and fills the NPC lines' $G tokens) tabs; `#/journal` redirects to Characters. Lore (`pages.lore`, `#/lore`) is the heart: `web/lib/tales.js` `tales()` lists every storyline and standalone quest that has been started, `tellTale()` writes the finished ones as young-adult third-person narratives with a whole story arc (parts are acts, not one per quest; no character names, an unnamed adventurer whose pronouns come from `settings.taleVoice` chosen on the Lore page, male by default, never they/them; `#/lore/tale?id=<storylineId|q<questId>>`, `&pretend=1` tells one ahead of time; `rollUp()` folds class-only variants of one event, the letters to five teachers, into a single chapter told once); the tale page is a wide two-column spread (`.storybook .book-part`); the page is a treasure-chest shelf of tale covers (`.shelf`, `.tale`, `.storybook` in styles.css). Texts (books, plaques, overheard lines, conversations) is Lore's last tab (`#/lore?show=texts`, `pages.texts`). Quests is one menu (`questZonesPage`): continents plus Class, Profession, Epic, Legendary, Ahn'Qiraj War and Invasion groups built from `tree.sorts` (`QUEST_GROUPS`; rows carry `sort: true` and a negative `zoneId`; `rpgMenu`'s `listLabel` says "9 classes" / "12 professions" and nothing for the single-row groups), with Logged and Notes as footer links. The sidebar never scrolls as a whole: only `nav` scrolls when its links do not fit, the brand and `.status` stay put. Data notes (`dataNotes()`, cached on `derived().notes`): first-hand quest titles/objectives and NPC names that differ from the database are tagged `first-hand` and listed under Quests › Notes, with a toast when new ones appear. Map images are cached in IndexedDB and reused as object URLs (`cachedMapImage` in maps.js), refreshed quietly after a day. Locations pins are your own sightings of the people met, creatures hunted and objects opened in the zone (`pinsFor` → `ownSpots`; the database's spawn points are never drawn), every pin a link; `#/map/<id>` is the shared map of the account's data collection (encounters, loot, quests, lore, routes); a character's own moments (deaths, close calls, level-ups, marks, screenshots; `personal` markers with `who` in maps.js) appear only when it is opened from that character's Completion tab with `?who=<key>`, as do the route lines, the GeoJSON's routes and the route replay; the time-spent heat is the whole account's on every view. `coverageWho()` defaults to everyone. Map layers are remembered in localStorage (`chronicler.mapLayers`, default quest + route). Deleting a character: `deleteCharacter` → `CloudStore.deleteSessions` + `settings.deletedSessions` (machine.js never re-uploads them). Overview: `progressCharts` (playtime, gold, level, quests) and `liveFeed` from `state.live` (refreshed every 5 s by `startFeedTimer`). Maps: `web/lib/maps.js` (pins, heat, quest trails, nearest services, GeoJSON) + `wireMap` in app.js; loose ends in `web/lib/coverage.js`. Recordings: the recordings folder is the source of truth on the Mac (`scanRec` every 20 s): a video that appears and keeps growing (`GROWING_FOR` 45 s since its last write) is a recording under way (row `source: 'file'`, no duration; `followRecordings` on the PC starts a stream session for `obs` or `file` game rows), one that stopped growing has ended; a start comes from the name (`startFromName`, OBS's pattern) or from the file's own movie header (`web/lib/mov.js` `readMovieInfo`: mvhd creation time and duration, QuickTime/MP4/ProRes, box headers only; MKV needs the name), the end from lastModified or the header's duration. `resolveRecordings` gives each file a `role` (`recordingRole(name, path)`: `cam …`/`camera …`/`face …` or a `cam`/`camera`/`face` folder → `cam`; `overlay …`/`ui …`, an `overlay` folder or `<stem>.overlay.mp4` → `overlay`; else `game`) and pairs every companion from the same machine whose time overlaps a game recording (starting no more than 5 s after it and covering at least its first 30 s; `companions` with `offset`, negative when it began earlier, `covers`; the first pairing sets the companion's timing, sync included; one always-on camera file serves several game recordings); `derived().recordings` holds only the game ones (`allRecordings` has every file); **files OBS split off are one recording**: `startFromName` reads the underscores of a continuation file (`gameplay_2026-09-27_15-06-30.mp4`) as the pattern's spaces, and `resolveRecordings` folds a file of the same role and machine that begins within 3 s of the previous one's end (`CONTINUES`; lengths come from the movie header, read for every finished movie file in `scanRec`) into it as `parts` (`{ name, path, duration, offset }`, the head's `duration`/`end` become the whole), for camera chains too (a companion carries `parts`); the list shows an "N parts" chip, the recording page a "Split into N files" panel, `wirePlayer`'s `player` (`pos()`, `seek(sec, play)`) plays the parts as one video (loading the part that holds the time, `ended` → the next), and machine.js `followRecordings` walks back to the chain's first file (`CONTINUES_MS`, or the previous file still under way) so a split never starts a second stream session; `toFCPXML` lays parts end to end on one track (`lay()`, clip ids `clipitem-v1`/`clipitem-a1`, `clipitem-c1v1`…) and companions on their own tracks (a negative offset trims the head). The Mac rig that works (tested): two Source Record filters, gameplay on Apple VT HEVC 70 Mbps (plays in Chrome), camera on hardware ProRes 422 in `.mov` (Proxy/LT fall back to a software encoder and stutter; H.264/HEVC for the camera shares the gameplay's engine and stutters too); the camera file is shrunk afterwards by a launchd helper on the Mac (`web/shrink/install.sh` + `shrink.sh`, served by Netlify, installed from This computer › Session package › Camera files: ffmpeg `hevc_videotoolbox` 16 Mbps to `cam ….mp4`, length checked, the ProRes to the Trash; the helper does nothing until the `.compendium-shrink-now` flag is in the folder and clears it when done, writing `.compendium-shrink-status`; app.js `runBatch()` (Recordings › "Process outstanding sessions (overnight)", `batch` state, `outstandingPackages()`) writes the flag (`machine.writeRecText`), builds every outstanding package oldest first, waits for each shrunk `.mp4` when `settings.sessionPack.shrinkCam` (gives up after 20 min of no shrinker activity, or 3 h of silence), and removes the flag on Stop; `sessionPack.auto` (off by default) is the only thing that builds on its own; `sessionPack.folder` remembers the path; `scanRec` retires a row whose file was replaced by one with the same stem and another extension); one-click recording: the sidebar's ● Record / ■ Stop pill (`toggleSourceRecord`, `machine.setSourceRecord`, `sourceRecordFilters` via `GetInputList` + `GetSourceFilterList`, filters of kind `source_record_filter`, polled every 10 s into `machine.srec`) sets every Source Record filter's `record_mode` to 1 (Always) or 0 (None) with `SetSourceFilterSettings`, so OBS's own recording and stream stay off and the folder scan turns the files into recordings; `config.obsMore` companion OBS instances (keys `cam`, `overlay`, `--multi --websocket_port`, `ObsLink`s whose recording follows the main one) remain optional. The recording size lives in `settings()` (`width`/`height`/`fps`, set on This computer; 3840×2160 for 4K) and feeds every export (`toFCPXML`, `toShortXML` source size, `toEpisodeXML`, the overlay pack); `drawStill` designs its cards at 1080p and scales them to the frame. `docs/PUBLIC.md` lists what must change before the tool goes public (the tale voice picker was removed in 1.0, tales say "him"). Motion/animation lives at the end of `web/styles.css` under "Glow-up" and respects prefers-reduced-motion; `route()` adds the `enter` class, staggers `--i`, counts numbers up, and slides the nav glow; on the same path with other parameters (a tab or filter, `state.lastRoute`) top-level children whose HTML did not change get `.still` and do not animate, and the scroll position is kept. Data notes only compare quest titles, description-style objective text (never the tracker's x/y lines) and NPC names; spawn and drop data are never compared. Theme tokens are at the top of styles.css: Alliance blue (`--ally*`) and Horde red (`--horde*`) as equals, aliased onto the old names (`--gold*` = blue for headings/links/progress, `--cyan*` = red for glows/icons/live), the brand title a blue-to-red gradient (`.brand-text`); every counter and percentage uses `--num` (the sans, lining tabular figures), never the serif; the Lore nav icon and hero share one inline treasure-chest SVG (the hero's is gold-gradient filled, with a chest light, rising sparks, an opalescent drift and a shifting title, all off under prefers-reduced-motion; the hero holds only the chest, the title and three counters); no hard-coded colours elsewhere. Reset: `CloudStore.deleteAll` + `settings.resetAt` (machine.js skips older sessions/recordings).
- Quest database: `web/data/classic/*.json` (quests, npcs, objects, items, zones, spawns) generated by `tools/import-questie.js` from Questie's repos (GPL-3.0; keep the `source` field). `web/lib/questdb.js` indexes it (`indexDB`, `questState`, `zoneCoverage`, `unfoundGivers`, `zoneRares`); app.js lazy-loads it with `questDB()`/`spawnTable()`, `coverageWho()` picks the character (`state.coverageWho`), and quest/NPC/zone/map pages fall back to database-only views (`dbQuestPage`, `dbNpcPage`, `dbZonePage`). `CLASSIC_ZONE_IDS` in maps.js maps UiMapID → areaId (Wowhead map images are by areaId).

the game writes the file only when its ~64 KB buffer fills, so ~80 KB of hidden `CHRONPAD~` filler lines follow each message in one tick after 0.3 s of quiet (`/comp live pad KB`, `settings.livePadKB`; 1.0.3, so a line reaches the overlay in about two seconds; the heartbeat after a level-up carries the new level, and `LiveState` never lets a heartbeat lower the level; 1.0.4 sends the quest log's ids as a `G` line with every heartbeat and on the first `QUEST_LOG_UPDATE` after login, with a quiet `Q~accept` (sixth field `1`, no NEW QUEST callout) for quests the overlay was never told about, and `LiveState`'s `questlog` event marks tracked quests missing from the log `gone`, so a missed turn-in never lingers on the tracker; 1.0.5 names the quest in every progress line (`Q~progress~qid~text`, `questOfObjective` in Compendium.lua matches the message against `GetQuestLogLeaderBoard`, retrying once after 0.3 s), and `LiveState` files progress under that quest, creating it if unheard of, falling back to the old guess only for id-less lines); `web/lib/live.js` decodes `Logs\WoWChatLog.txt` (`eventsFromChatLog` drops a doubled line) and keeps `LiveState`; `machine.changed(topic)` (data/live/voice/obs/clock/wow) → app.js `changed(topic)` redraws only pages listed for that topic in `PAGE_TOPICS`, so live events never rebuild maps or tables; the overlay polls every 2 s with `p_seq` (schema v4 `live_state(p_token, p_seq)` answers `{seq}` when unchanged) and overlay windows on one computer share one poller over a BroadcastChannel; the PC only touches `updated_at` when nothing changed (`touchLive`); machine.js tails the file every second on the gaming PC (`purgeChatLog` empties it when >1 MB and unwritten for 3 min, i.e. logged out) and upserts the `live` row (token in `settings.liveToken`); `web/overlay.html` + `overlay.js` (OBS browser source) polls `live_state(token)` (an RPC in the schema, anon-readable). Kill lines carry the unit's rank (`ns.rankOf(guid)` from Capture's `seen` table); `LiveState` marks the first loot/kill of a kind this session (`first`) and machine.js `markNovel` marks those the wiki has never had (`novel`; account-wide, not per stream session: the wiki decides, and localStorage `chronicler.live.known` remembers what was already called out until the play session is uploaded at logout; cleared by a full delete), which the overlay calls out as NEW ITEM (with the item's art, `newItem`) and FIRST HUNT / ELITE HUNTED / RARE HUNTED / WORLD BOSS SLAIN (`hunted`, rares and bosses every time with a flash and shake). In the all-in-one window the eight positions are HUD-safe percentages of the frame (clear of the player frame, minimap, objectives, right bars, chat and action bars; `.pos-*` in overlay.css) and widgets sharing a position stack in one `.slot` (top centre is a row: timer then counters); defaults timer+counters tc, tracker ml, kills bl, toasts br (`DEFAULT_OVERLAY`; settings saved with the old layout are migrated on the Live page). ## Checks

- `npm test` runs everything. The addon tests need `lua5.1` (apt-get install lua5.1); they run the real addon against `test/addon/harness.lua`.
- `npm run serve` runs the web app locally; `node tools/build-web.js` copies the addon into `web/addon` (Netlify runs it on deploy).
- After changing the addon, regenerate the fixture: `lua5.1 test/addon/harness.lua addon/Compendium test/fixtures/Compendium.lua`.
- New client versions: `npm run add-interface -- <number>`.
- Quest data refresh: clone `Questie/QuestieDB` (sparse `data/Classic src`) and `Questie/Questie` (sparse `Database Localization`), then `node tools/import-questie.js <QuestieDB> <Questie>`; `test/questdb.test.js` checks the generated files.
- Schema changes go at the end of `supabase/schema.sql` as a new "Version N" block (idempotent); the user re-runs the whole file in Supabase › SQL Editor and must be told so.
