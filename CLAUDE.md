# Chronicler

WoW addon (`addon/Chronicler`, Lua 5.1) + a no-build web app (`web/`) hosted on Netlify with data in Supabase (`supabase/schema.sql`). The gaming PC (Windows) and recording computer (Mac, OBS) each run the web app in Chrome; the server clock bridges them. See README.md and docs/ROADMAP.md.

## Working with the user

- Don't include the ZIP download link in messages. The addon installs and updates from the web app (This computer › Update addon). Netlify deploys this branch automatically on every push: never ask the user to trigger a deploy (each manual deploy costs build minutes on top of the automatic one). Batch related changes into one push. Only two things need telling: re-running `supabase/schema.sql` after a schema change, and updating the addon in game after an addon change.
- Whenever you mention a file, say where it is or how to open it: a GitHub link for files in this repo
  (`https://github.com/adelrio3/streamer-app/blob/<branch>/<path>`), the full Windows path for files on their PC
  (e.g. `C:\Program Files (x86)\World of Warcraft\_classic_era_\WTF\Account\<ACCOUNT>\SavedVariables\Chronicler.lua`),
  or the web address / menu path for external services (Supabase, Netlify). Don't say "the schema file" or "the README" bare.
- They play Classic Era (interface 11509 as of 1.15.9) on a Windows PC (Chrome can't open Program Files, so WoW gets moved to `C:\Games\World of Warcraft`) and record with OBS on a separate Mac (no file sharing between them), editing in Premiere Pro.
- Give exact values to enter and direct links (Supabase dashboard links can use `https://supabase.com/dashboard/project/_/...`), so they don't have to hunt or guess.

## Web app layout

- `web/index.html` is a sidebar shell (Chronicle: Overview, Characters, Lore / World: Locations, Quests, Storylines, Bestiary, People, Items / Footage: Recordings, Highlights, Shorts, Episodes, Footage finder, Screenshots, Marks, Narration / Stream / System); pages live in `web/app.js` as `pages.<name>` and use `pageHead`, `tabsHtml`, `crumb`, `facts`, `table`. **World is a personal wiki**: it lists only what this account has come across (from the addon's log), measured against everything in Classic (the database). A name is grey (`wikiName`, class `dim`) until done: a creature until killed (kill count in the name), a person until met, an item until obtained (`dim-item`), a quest until turned in, a zone until visited; nothing from the database is listed that the player has not found, and the whole-game totals only feed percentages. The World entries in the sidebar carry a percentage (`navPercents`, cached on `derived().navPct`, `.pct` spans with a shine when they change). Locations and Quests share `rpgMenu` (continents → zones by level → the page; `.rpg` in styles.css): it re-renders only what changed on clicks (`history.pushState`, no route), folds to a rail once a zone is chosen (`.rpg--zone`), and takes `detail(continent, zone)` / `after()` from the page. Locations' page is the zone's wiki entry (its map via `wireMap('locMap')`, areas discovered, quests, people, creatures as found), Quests' page is the zone's quest progress with the quests you logged there; the "Class, profession & events" tab counts those on their own. A quest page (`pages.quest`) shows the quest objectively (text as read, DB givers/turn-in/objectives and their spawn pins) with your history last; `requirementText(q)` names the faction/race/class when a quest is not for everyone and `excluded` (not in the game) quests are hidden. People: `peopleStatus(n)` = met / seen / ambient (nothing to say or sell: met on sight); world.js merges NPCs with the same name into one entry (`mergeNpc`, `ids`). Loot `src` is `bought` at a vendor and `mail` at a mailbox (`ns.lootContext` in Capture.lua). The Footage nav entries carry `data-needs="records"` and hide on a computer that does not record. Storylines uses the same `rpgMenu` (continents → the zone each chain begins in → the chains started there; class/profession chains under Elsewhere) and lists only chains you have set foot in (chapters you have not found stay grey). **Nothing undiscovered from the database is ever shown except locations**: map pins (no count badges) come only from your own sightings and the verified spawn points of people met, creatures hunted and objects opened (`pinsFor`, `dbQuestBody`); `dbMapPins` returns nothing, and an unfound quest, NPC or zone page (`dbQuestPage`, `dbNpcPage`, `dbZonePage`) shows a name, a zone and a count at most. Bestiary is `world.creatures` by kind (`CREATURE_TYPES`), People is `world.people` by zone, Items is `world.items` by kind → type (`itemKind` folds Projectile and Quest into Miscellaneous as its Projectiles / Quest items types, `MISC_KINDS`/`MISC_SUBS` keep the totals right; a kind's page is tabs, "All …" first, over one table; totals from `web/data/classic/itemdb.json`, `itemTable()` lazy-loads it; `obtained` = looted/received/created/worn/carried), Gathering is `world.objects`. Characters: each character page has Dashboard (`characterDashboard`: where they are, standing, quests in the log, storylines in hand, latest milestones), Progress (stats, gear, quests, recordings), Places (zones visited, maps explored, loose ends; `#/zone/<name>` is a zone's journal detail) and Journal (the character's first-person account by `web/lib/narrative.js` `journalEntries()`: I/me/my, exactly one entry per outing, the errands handed in retold as deeds from their objective text ("For Gornek I thinned ten Mottled Boars", never a quest title), grouped by who asked, length scaled to how much got done (one paragraph for a quiet outing, up to three for a busy one, `paragraphs`); `info.sex`, which the addon records with `UnitSex`, is shown as "Male Troll Hunter" and fills the NPC lines' $G tokens) tabs; `#/journal` redirects to Characters. Lore (`pages.lore`, `#/lore`) is the heart: `web/lib/tales.js` `tales()` lists every storyline and standalone quest that has been started, `tellTale()` writes the finished ones as young-adult third-person narratives with a whole story arc (parts are acts, not one per quest; no character names, an unnamed adventurer whose pronouns come from `settings.taleVoice` chosen on the Lore page, male by default, never they/them; `#/lore/tale?id=<storylineId|q<questId>>`, `&pretend=1` tells one ahead of time; `rollUp()` folds class-only variants of one event, the letters to five teachers, into a single chapter told once); the tale page is a wide two-column spread (`.storybook .book-part`); the page is a treasure-chest shelf of tale covers (`.shelf`, `.tale`, `.storybook` in styles.css). Texts (books, plaques, overheard lines, conversations) is Lore's last tab (`#/lore?show=texts`, `pages.texts`). Quests is one menu (`questZonesPage`): continents plus Class, Profession, Epic, Legendary, Ahn'Qiraj War and Invasion groups built from `tree.sorts` (`QUEST_GROUPS`; rows carry `sort: true` and a negative `zoneId`; `rpgMenu`'s `listLabel` says "9 classes" / "12 professions" and nothing for the single-row groups), with Logged and Notes as footer links. The sidebar never scrolls as a whole: only `nav` scrolls when its links do not fit, the brand and `.status` stay put. Data notes (`dataNotes()`, cached on `derived().notes`): first-hand quest titles/objectives and NPC names that differ from the database are tagged `first-hand` and listed under Quests › Notes, with a toast when new ones appear. Map images are cached in IndexedDB and reused as object URLs (`cachedMapImage` in maps.js), refreshed quietly after a day. Locations pins are verified spawn points from the database for the people met, creatures hunted and objects opened in the zone (`pinsFor`), every pin a link; the per-character encounter pins stay on `#/map/<id>`. `coverageWho()` defaults to everyone. Map layers are remembered in localStorage (`chronicler.mapLayers`, default quest + route). Deleting a character: `deleteCharacter` → `CloudStore.deleteSessions` + `settings.deletedSessions` (machine.js never re-uploads them). Overview: `progressCharts` (playtime, gold, level, quests) and `liveFeed` from `state.live` (refreshed every 5 s by `startFeedTimer`). Maps: `web/lib/maps.js` (pins, heat, quest trails, nearest services, GeoJSON) + `wireMap` in app.js; loose ends in `web/lib/coverage.js`. Motion/animation lives at the end of `web/styles.css` under "Glow-up" and respects prefers-reduced-motion; `route()` adds the `enter` class, staggers `--i`, counts numbers up, and slides the nav glow; on the same path with other parameters (a tab or filter, `state.lastRoute`) top-level children whose HTML did not change get `.still` and do not animate, and the scroll position is kept. Data notes only compare quest titles, description-style objective text (never the tracker's x/y lines) and NPC names; spawn and drop data are never compared. Theme tokens are at the top of styles.css (`--gold-rgb`/`--cyan-rgb` for glows; no hard-coded colours elsewhere). Reset: `CloudStore.deleteAll` + `settings.resetAt` (machine.js skips older sessions/recordings).
- Quest database: `web/data/classic/*.json` (quests, npcs, objects, items, zones, spawns) generated by `tools/import-questie.js` from Questie's repos (GPL-3.0; keep the `source` field). `web/lib/questdb.js` indexes it (`indexDB`, `questState`, `zoneCoverage`, `unfoundGivers`, `zoneRares`); app.js lazy-loads it with `questDB()`/`spawnTable()`, `coverageWho()` picks the character (`state.coverageWho`), and quest/NPC/zone/map pages fall back to database-only views (`dbQuestPage`, `dbNpcPage`, `dbZonePage`). Map layers `unfound` and `rares`. `CLASSIC_ZONE_IDS` in maps.js maps UiMapID → areaId (Wowhead map images are by areaId).
- Live overlay: addon `Live.lua` writes `CHRON1~…` lines (fields `~`, events `~~`) into the chat log with `SendSystemMessage` (local, no server; say/yell/channel chat from an addon is blocked without a hardware event, and `LoggingChat(false)` does not close the file) and turns on `LoggingChat`; the game writes the file only when its ~64 KB buffer fills, so ~80 KB of hidden `CHRONPAD~` filler lines follow each message (`/chron live pad KB`, `settings.livePadKB`); `web/lib/live.js` decodes `Logs\WoWChatLog.txt` (`eventsFromChatLog` drops a doubled line) and keeps `LiveState`; `machine.changed(topic)` (data/live/voice/obs/clock/wow) → app.js `changed(topic)` redraws only pages listed for that topic in `PAGE_TOPICS`, so live events never rebuild maps or tables; the overlay polls every 2 s with `p_seq` (schema v4 `live_state(p_token, p_seq)` answers `{seq}` when unchanged) and overlay windows on one computer share one poller over a BroadcastChannel; the PC only touches `updated_at` when nothing changed (`touchLive`); machine.js tails the file every second on the gaming PC (`purgeChatLog` empties it when >1 MB and unwritten for 3 min, i.e. logged out) and upserts the `live` row (token in `settings.liveToken`); `web/overlay.html` + `overlay.js` (OBS browser source) polls `live_state(token)` (an RPC in the schema, anon-readable). Kill lines carry the unit's rank (`ns.rankOf(guid)` from Capture's `seen` table); `LiveState` marks the first loot/kill of a kind this session (`first`) and machine.js `markNovel` marks those the wiki has never had (`novel`), which the overlay calls out as NEW ITEM (with the item's art, `newItem`) and FIRST HUNT / ELITE HUNTED / RARE HUNTED / WORLD BOSS SLAIN (`hunted`, rares and bosses every time with a flash and shake). Params: `show=` (all-in-one), `widget=<one>` (a single widget filling its window, `WIDGET_SIZES` in app.js), `bg=<hex>` (chroma key), `demo=1`, `scale=`, `theme=<race>` (pins a race theme; otherwise `html[data-race]` follows `character.race` from the addon's `B`/`H` lines: per-race tokens, textures and motion at the end of overlay.css, `RACE_FX` particles in overlay.js). The Live page builds the addresses (`settings.overlay` incl. `bg`, `settings.liveCounters`), pops out previews with `window.open`, and the Drops page uses `pastLoot` + the live loot after `uploadedUntil`.
- Storytelling: `web/lib/story.js` (`storylines(db, ctx)`: quest chains via `next`/`pre`/`preAll`, topologically ordered, named after the finale; `storylineOutline` Markdown) → World › Storylines (`#/storylines`, `#/storyline/<minQuestId>`). `web/lib/shorts.js` (`findShorts` windows around `findHighlights` moments, merged; `toShortXML` 1080×1920 sequence) → Footage › Shorts. `web/lib/episode.js` (`assembleEpisode` from `findSegments` per map id, turn-in markers; `toEpisodeXML`, `episodeChapters`) → Footage › Episodes. `web/lib/replay.js` (`planReplay`, `routeAt`, `drawReplayFrame`) → the map page's Route replay panel (`replayPanel`/`wireReplay` in app.js: WebM via MediaRecorder, PNG sequence via zip.js). `toSequenceXML` in exports.js lays clips end to end for both.
- Voice notes: `web/lib/voice.js` (Web Speech API) → `voice` table; `buildTimelines(..., voice)` adds `voice` events with `until`; category `voice` ("Narration"), page `#/narration`, export `narration`.
- Objects you interact with (cactus, chest, herb) are named in Capture.lua from `UNIT_SPELLCAST_SENT` (the opening cast's target) or the last tooltip, remembered in `ChroniclerDB.objects` and recorded once as an `object` event; world.js keys them `o<id>` so named and unnamed sightings merge, and flags `unnamed` ones.
- Overlay pack: `web/lib/overlaypack.js` (`planOverlays`, `drawStill` on a canvas, `toOverlayXML`) + `web/lib/zip.js`, from the recording page (`buildOverlayPack`). Addon errors: `ChroniclerDB.errors` → `readAddonLog().errors` → `settings.addonErrors` (machine `collectErrors`) → This computer › Addon errors → `errorDump()`.
- The headless two-computer smoke test lives in the session scratchpad (`cloud-smoke.cjs`), not the repo; it fakes Supabase, folders and OBS.

## Checks

- `npm test` runs everything. The addon tests need `lua5.1` (apt-get install lua5.1); they run the real addon against `test/addon/harness.lua`.
- `npm run serve` runs the web app locally; `node tools/build-web.js` copies the addon into `web/addon` (Netlify runs it on deploy).
- After changing the addon, regenerate the fixture: `lua5.1 test/addon/harness.lua addon/Chronicler test/fixtures/Chronicler.lua`.
- New client versions: `npm run add-interface -- <number>`.
- Quest data refresh: clone `Questie/QuestieDB` (sparse `data/Classic src`) and `Questie/Questie` (sparse `Database Localization`), then `node tools/import-questie.js <QuestieDB> <Questie>`; `test/questdb.test.js` checks the generated files.
- Schema changes go at the end of `supabase/schema.sql` as a new "Version N" block (idempotent); the user re-runs the whole file in Supabase › SQL Editor and must be told so.
